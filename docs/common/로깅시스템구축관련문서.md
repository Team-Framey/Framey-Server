## Logging System 가이드

> 작성일: 2026.09.27  
> 작성자: [@young0311](https://github.com/young0311)

### 기능

`common-monitoring` 기능

- **TraceId 생성**
    - HTTP 요청마다 고유 랜덤 TraceId를 생성.
    - 응답 Header(`X-Trace-Id`)에 TraceId를 포함 .

- **주요 비즈니스 활동 자동 로깅**
    - `@LogActivity`가 붙은 메서드의 시작/성공/실패와 실행 시간을 자동으로 기록.

- **공통 Logback 설정**
    - Console과 File 출력 형식, Rolling 정책 등을 공통으로 관리.

- **Auto Configuration**
    - `MonitoringAutoConfiguration`이 `TraceIdFilter`와 `LogActivityAspect`를 자동으로 Bean으로 등록

### 새 서비스 모듈에 적용 방법

#### 1. `settings.gradle`에 모듈 등록합니다

루트 `settings.gradle`에 새 모듈을 추가하면 됩니다.

```gradle
rootProject.name = 'server'

include ':common:common-monitoring'
//ex) include 'identity-service' : identity-service 모듈 추가
```

####  2. `build.gradle`에 의존성을 추가합니다
새로운 서비스 모듈의 `build.gradle`에 `common-monitoring`을 의존성으로 추가해야

```gradle
dependencies {
    implementation project(':common:common-monitoring')
}
```

아래 기능을 별도 Bean 등록 없이 사용할 수 있습니다!

- `@LogActivity`
- `TraceIdFilter`
- `LogActivityAspect`
- Framey 공통 Logback 설정

#### 3. 각 서비스 모듈의 설정파일에 이름 지정해주세요
각 실행 모듈의 설정 파일에 자신의 애플리케이션 이름을 지정하면
Console 및 File 로그에 `[서비스명]` 형태로 출력됩니다.

```yaml
spring:
  application:
    name: identity-service'
```

예를 들어 `spring.application.name=identity-service`라면 로그는 다음과 같이 출력되게됩니다.!

```text
20:31:12.123 INFO  [identity-service] [a72bc981] ...
```

#### 4. Logback 설정

`common-monitoring`에 기본 `logback-spring.xml`이 포함되어 있으므로, 별도의 Logback 파일이 없어도 공통 설정이 자동으로 각모듈에 적용됩니다.
서비스에서 별도의 `logback-spring.xml`을 추가하면,  
`common-monitoring`의 기본 설정 대신 해당 설정이 적용됩니다.

##### (참고) 공통 Logback 설정 관련

공통 Logback 설정파일은 `common-monitoring`내에 있습니다.

```text
common/common-monitoring/
└── src/main/resources/
    └── logback-spring.xml
```

#### 5. `@LogActivity` 사용 방법

주요 비즈니스 메서드에 `@LogActivity("")`을 선언하면됩니다

(예시)
```java
@LogActivity("사진 업로드")
public PhotoResponse upload(PhotoRequest request) {
    return photoUploader.upload(request);
}
```

`LogActivityAspect`가 메서드 실행 전후를 감싸서 다음을 자동으로 기록하고있습니다

- `[START] 활동명`
- `[SUCCESS] 활동명 | elapsed=...ms`
- `[FAIL] 활동명 | elapsed=...ms` (예외 발생 시)

##### (case) 성공했을 경우

```text
20:31:12.102 INFO  [photo-service] [a72bc981] c.f.m.aspect.LogActivityAspect - [START] 사진 업로드
20:31:12.351 INFO  [photo-service] [a72bc981] c.f.m.aspect.LogActivityAspect - [SUCCESS] 사진 업로드 | elapsed=249ms
```

##### (case) 실패했을 경우

```text
20:32:04.102 INFO  [photo-service] [c128ab31] c.f.m.aspect.LogActivityAspect - [START] 사진 업로드

20:32:04.183 ERROR [photo-service] [c128ab31] c.f.m.aspect.LogActivityAspect - [FAIL] 사진 업로드 | elapsed=81ms
java.lang.IllegalStateException: 이미지 저장 실패
    at com.framey.photo.service.PhotoService.upload(PhotoService.java:42)
    ...
```

`[FAIL]` 로그에는 예외 객체를 함께 전달하므로 Stack Trace가 함께 출력됩니다.

##### (참고) 로그 필드 의미

```text
20:31:12.351        → 로그 발생 시간
INFO                → 로그 레벨
[photo-api]         → spring.application.name
[a72bc981]          → TraceId
c.f.m.aspect.LogActivityAspect → 로그를 출력한 Logger
[SUCCESS]           → 작업 결과
사진 업로드         → @LogActivity에 지정한 활동명
elapsed=249ms       → 메서드 실행 시간
```

##### (참고) `@LogActivity` 사용 기준

`@LogActivity`는 
사용자가 수행하는 주요 비즈니스 행위나 운영 중 추적할 가치가 있는 작업에 사용할 어노테이션입니다.!

###### `@LogActivity` 어노테이션 사용 예시

```java
@LogActivity("사진 업로드")
public PhotoResponse upload(...) { }

@LogActivity("콜라주 생성")
public CollageResponse createCollage(...) { }

@LogActivity("회원 가입")
public MemberResponse signup(...) { }

@LogActivity("이미지 변환")
public ImageResponse convert(...) { }
```

###### 이러한 경우엔 `@LogActivity` 어노테이션 사용을 지양하면 좋을 것같습니다.!

```java
// 단순 Getter
@LogActivity("회원 이름 조회")
public String getName() { return name; }

// 단순 Mapper
@LogActivity("DTO 변환")
public PhotoResponse toResponse(Photo photo) { ... }

// 단순 내부 유틸리티
@LogActivity("파일명 생성")
private String createFileName() { ... }
```

이런 메서드까지 기록하면 중요한 로그가 묻힐것같아
기본적으로 **주요 Service 비즈니스 작업 단위**를 기준으로 사용하면 좋을 것 같습니다.

##### (참고) TraceId 동작 방식

HTTP 요청이 들어오면 `TraceIdFilter`가 요청마다 새로운 TraceId를 생성하고있습니다

```text
a72bc981
```

TraceId는 다음 흐름으로 전달됩니다

```text
HTTP Request
      ↓
TraceIdFilter
      ↓
TraceId 생성 (a72bc981)
      ↓
MDC 저장
      ↓
Controller
      ↓
Service
      ↓
Repository
      ↓
HTTP Response
```

해당 요청을 처리하는 동안 발생하는 로그에는 동일한 TraceId가 포함됩니다.

```text
20:40:01.012 INFO  [photo-api] [a72bc981] ... - 요청 처리
20:40:01.032 INFO  [photo-api] [a72bc981] ... - [START] 사진 업로드
20:40:01.201 DEBUG [photo-api] [a72bc981] ... - 이미지 저장
20:40:01.291 INFO  [photo-api] [a72bc981] ... - [SUCCESS] 사진 업로드 | elapsed=259ms
```

+) HTTP Response에 TraceId 포함
생성된 TraceId는 HTTP 응답 헤더에도 포함하고있습니다.!

```http
X-Trace-Id: a72bc981
```
### Log Level

#### DEBUG

개발 및 문제 분석을 위한 상세 정보에 사용

```java
log.debug("레이아웃 조회. layoutId={}", layoutId);
```

#### INFO

정상적인 주요 비즈니스 흐름에 사용합니다.

```java
log.info("콜라주 생성 완료. collageId={}", collageId);
```

`@LogActivity`의 `[START]` / `[SUCCESS]` 로그도 `INFO`로 출력하고있습니다

#### WARN

확인이 필요한경우에는 WARN Level를 사용하고있습니다
```java
log.warn("이미지 일부 처리 실패. failedCount={}", failedCount);
```

(예시)

- 재시도 발생
- 일부 데이터 처리 실패
- Fallback 수행
- 예상하지 않은 입력이지만 복구 가능

#### ERROR

현재 작업이나 요청이 정상적으로 완료되지 못한 경우입니다

```java
log.error("이미지 저장 실패. imageId={}", imageId, exception);
```

`@LogActivity` 실행 중 예외가 발생하면 `[FAIL]` 로그가 `ERROR`로 자동 기록하고 있습니다

##### 로그 작성 권장 형식

값의 의미가 명확하도록 `key=value` 형태를 권장합니다

권장:

```java
log.info("콜라주 생성 완료. collageId={}, imageCount={}", collageId, imageCount);
```

결과:

```text
콜라주 생성 완료. collageId=123, imageCount=6
```

다음과 같이 값만 나열하는 방식은 로그만 보고 각 값의 의미를 알기 어렵기 때문에 되도록이면 피해주세요.!

```java
log.info("콜라주 생성 완료 {} {}", collageId, imageCount);
```
